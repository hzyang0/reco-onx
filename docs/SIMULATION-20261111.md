# 优先改进与模拟用户验证（2026-11-11）

## 已完成的改进

当前需求现在可以直接编辑：区域、品类、完整商品名、严格／优先匹配、到手预算、送达分钟和数量。清空预算或时限代表显式解除对应限制；清空商品代表不限款式。切换品类清空旧商品名，提交时重新生成请求标识；弱网重试则保留完整结构化请求。新会话和用户切换隐藏旧表单。编辑器在手机窄屏也可访问。

界面使用现有后端 `LocalConstraints` 校验，补齐 WebSocket 到请求模型的结构化参数传递。编辑预算不会撤销未解决的乳糖／过敏要求，面板显示未解决要求并提示用对话明确撤回。

全新语言场景首次运行发现：焦糖拿铁和引号内的榛果拿铁被缩为拿铁。现在对明确点名及引号包围的咖啡名称保留完整词；严格模式没有目录匹配时返回无匹配。仍是有限语言规则，不保证任意品牌、口味、组合订单的识别。

补充 WebSocket 非法 JSON、数组、null、数字测试，返回错误后可以继续接收下一条消息，不再因 payload 类型崩溃。

## 使用方法

发起一次本地生活查询，在“当前需求”面板修改字段，点击“确认条件并重新查询”。新商品名可以直接填入，无须依赖自然语言词表。字段单位是元、分钟、件；报价仍不预占库存。

现有完整学习手册继续适用。后续优先安排真实同学自由措辞试用，尤其观察澄清、替代确认和未知商品名称；公开部署前仍需要生产身份鉴权和真实数据来源。
