# 独立措辞挑战集设计说明

- 数据文件：`language_challenge_v1.json`；24 个独立会话场景、33 次请求。预期状态为 completed 23 次、no_match 4 次、clarification 6 次。
- 本挑战集由独立 agent 编写，不是真实用户数据、不是人类留出集，也不能据此声称已证明自然用户效果。作者没有读取 `agent-service/app`、`agent-service/tests`、既有 evaluation 数据或 validation 报告，也没有运行待测系统以调整期望。
- 可见来源仅为 `docs/LOCAL-LIFE-GUIDE.md` 与 `db/migration/V3__local_life_tools.sql`：前者用于业务范围、费用规则和状态语义，后者用于商品、区域覆盖、库存、门槛、配送与优惠事实。指南本身含公开示例和语言边界，所以隔离的是实现代码及已有评测信息，不能把它描述为完全未见产品文档的盲测。
- 只使用 north / south / east 三个区域、coffee / meal / grocery 三种品类、单一商品和 1–10 件数量。全部请求使用自然中文，不附结构化约束；不要求写入长期偏好。每个 case 必须使用新会话；同一 case 的 turns 顺序执行。
- 有效需求按业务语义确定期望，不依据当前解析器可支持的语法降低要求。措辞包含“跑腿钱”“封顶”“十六块九”“十八元五角”“一刻钟”“一个钟头”“能等的极限”、标题完整名称、“两份”和“一百二十元”。时间/预算等于边界允许。
- 多轮覆盖指定商品保留、数量/预算修改、时间约束解除、商品约束解除、预算解除、换品类清除旧商品、保留条件切换区域，以及不支持要求的澄清回合不应污染原有条件。区域地址词仅定位到已知区域，不期望解析真实楼栋地址。
- 两个明显歧义分别是“北区和东区之间”与“一杯或两杯都行”；不允许擅自选定区域或数量。不支持的零乳糖、完全不辣、指定时刻送达及奶/糖配方要求应先澄清，不能当作已满足。
- `intent` 只声明应验证的字段。`null` 明确要求清除或保持已清除状态；`product_query` 对完整商品名使用完整名称，对冷萃使用明确提出的款式词。评估若允许语义等价的商品查询，应事先说明等价准则，避免把任何更宽泛查询都视为同一要求。
- 已用独立的 V3 数据读取和业务公式计算核对全部 27 次 completed / no_match 的首选商品、总价或无结果预期。没有调用待测 API；此核对仅验证测试预期自身，不代表系统通过挑战集。
